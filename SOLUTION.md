# Решение

## Сколько заняло

1 ч 37 мин, включая настройку проекта, добавление скиллов и конфигов для инструментов.

## Что сделано и что не успел

Реализован экран матчей: карточки, фильтры, skeleton, ошибка и повтор, пустое состояние,
обновление и возраст последнего успешного ответа. Контракт описан в OpenAPI; типы,
Zod-схемы, Fetch-функция и хук TanStack Query сгенерированы Kubb 5.
По уточнению задания используется явный mock-сценарий `matches` с `data/matches.json`:
ответ проходит через тот же транспорт и generated validation. В сценарии есть задержка
350 мс для видимого skeleton. Путь JSON описан в OpenAPI; неиспользуемый src/config.ts удалён.
Реальный HTTP-источник сейчас не используется. Общий клиент выбирает mock-режим
по EXPO_PUBLIC_API_MOCK_MODE; технический baseURL в этом режиме не влияет на выбор
маршрута. App.tsx не содержит настройки транспорта. Для перехода на сеть нужно отключить
`EXPO_PUBLIC_API_MOCK_MODE=true` в .env и задать доступный EXPO_PUBLIC_API_URL; после изменения env перезапустить Expo.
Добавлены звёздочки избранного: один useFavorites на экран, состояние по ID и
сохранение между запусками в localStorage (native polyfill expo-sqlite, на web —
хранилище браузера). Отсутствующие/повреждённые данные дают пустое избранное,
дубли ID нормализуются; при отказе storage экран работает в памяти и показывает
неблокирующее сообщение. Сохраняются только ID под ключом matches:favorites:v1.
Подготовлен будущий PUT /favorites/{matchId} с isFavorite=true/false и generated
useSetMatchFavorite; в UI он не вызывается, потому что backend отсутствует.
Комментарий об этом оставлен в MatchesScreen; переключение env не включает
серверное избранное автоматически.

## Решения

- «Предстоящие» включают scheduled и postponed: перенесённый матч ещё не завершён.
  live уже начался, но не завершён, поэтому отображается только во «Все».
  Фильтрация локальная по серверному статусу: JSON не поддерживает query-параметры,
  даты примера могут быть историческими. Порядок ответа сохраняется.
- Счёт проверяется на null, поэтому 0:0 и 3:0 сохраняются; null отображается как «—».
  startsAt=null показывает «Дата уточняется». Intl.DateTimeFormat без timeZone
  переводит UTC в часовой пояс устройства/браузера.
- Экран напрямую вызывает generated useGetMatches, который обслуживает загрузку, «Обновить» и «Повторить» через
  refetch. isLoading включает skeleton; isFetching блокирует обновление и показывает
  индикатор, сохраняя данные. Ошибка обновления не удаляет предыдущий результат.
  Пустой ответ и отсутствие совпадений фильтра показывают отдельный компонент
  «Нет запрашиваемых матчей» с пояснением, по центру свободной области экрана.
- QueryClient стабилен. Retry и обновление при focus/reconnect используют
  стандартные настройки TanStack Query; кешированные данные сохраняются при фоновом запросе. Generated queryFn передаёт AbortSignal; ответ проверяется generated Zod-схемой
  без дополнительных handwritten schemas и wrappers.
- UpdatedAgo получает dataUpdatedAt. До 60 секунд показывает секунды, после — целые
  минуты с округлением вниз и русскими окончаниями. Формы минут вынесены в константы.

## Баги из части 2

1. Звёздочки: Boolean(indexOf(id)) превращал -1 (не найдено) в true, а индекс 0 в false; push/splice меняли исходный массив, и setState с той же ссылкой мог не вызвать рендер. Теперь includes проверяет наличие ID, а функциональный updater создаёт новый массив, поэтому независимые и быстрые переключения работают предсказуемо.
2. «Обновлено N сек назад»: interval захватывал начальный seconds и снова выставлял 1, игнорировал since и не очищался при unmount. Это уже исправлено в add-matches-screen: возраст считается от времени последнего успеха, пересчитывается после обновления/возврата из фона, interval и подписка очищаются.

## Как я использовал ИИ

Использовал Codex для анализа исходного кода, реализации и проверок, а OpenSpec —
для описания требований и разбиения работы на changes. Настроил скиллы и инструкции
для агента, задавал архитектурные решения и проверял предлагаемые изменения.

Например, агент добавил лишнюю обёртку над generated hook и ручную Zod-валидацию —
я попросил использовать напрямую код, сгенерированный Kubb. Также убрал предложенное
агентом отключение стандартных retry/refetch TanStack Query и перенёс настройку
mock-режима в общий клиент через env. Структуру компонентов, локальное сохранение
избранного и детали интерфейса уточнял по ходу работы.

Агент выполнил typecheck, проверки OpenAPI и повторной генерации, форматирование,
OpenSpec validation, сборки web/iOS и браузерные проверки списка, избранного и таймера.
Постоянного набора автоматических тестов пока нет; Expo Go на реальном устройстве
не проверялся, а возврат из фона проверялся только моделированием в браузере.
