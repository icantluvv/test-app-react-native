## Why

Экран «Матчи тура» пока содержит только заголовок. Пользователю нужен список матчей с актуальными данными, понятными состояниями загрузки и возможностью отобрать нужные матчи.

## What Changes

- OpenAPI-контракт JSON-источника матчей: GET-путь и component schemas; Kubb 5 генерирует types, Zod schemas, Fetch methods, query keys/options и hooks.
- Явный mock-сценарий matches существующего транспорта возвращает data/matches.json (уточнение пользователя); ошибки не скрываются fallback.
- Загрузка generated hook TanStack Query; skeleton по isLoading, ошибка с повтором и пустой экран «нет запрашиваемых матчей».
- Фильтры «Все / Предстоящие / Завершённые» по серверному статусу.
- «Обновить» и «Повторить» вызывают refetch того же generated hook; данные сохраняются при ошибке обновления. UpdatedAgo получает время успеха из query.
- Корректные локальные дата/время, нулевой счёт, перенос без даты и русские статусы.
- Подключение и исправление `UpdatedAgo`; описание решений в `SOLUTION.md`.

## Capabilities

### New Capabilities

- `matches-screen`: загрузка, карточки, фильтрация, обновление и время последнего успешного получения матчей.

### Modified Capabilities

Нет существующих спецификаций.

## Impact

Затрагиваются `src/screens/MatchesScreen.tsx`, `src/components/UpdatedAgo.tsx`, узкая логика загрузки и представления матчей в `src/`, `SOLUTION.md`. Дополнительно меняются App.tsx (QueryClientProvider), OpenAPI paths/component schemas, generated output и публичные экспорты @repo/api, профильные API README. Неиспользуемый src/config.ts удаляется, конфигурация сервера/mock-режима переносится в env. Исходные данные не меняются. Роутер и новые runtime-зависимости не требуются. Избранное и другие части README не входят в эту фичу.

## Quality impact

- Риск P2: чтение данных и локальное состояние одного экрана, без записей на сервер.
- Проверки: typecheck, форматирование; сценарии сетевых состояний и таймера, граничные случаи счёта/даты/фильтров.
- В проекте нет настроенного test runner: основной план — воспроизводимые ручные проверки в браузере и Expo Go с контролируемыми ответами. Автоматизация требует отдельного согласованного setup и не объявляется существующей.
- Исходный URL содержит `OWNER/REPO`: реальный сетевой happy path ограничен доступностью источника; по уточнению пользователя выбран явный mock-сценарий с data/matches.json, реальная сеть не используется.
- Откат: вернуть изменения экрана, его вспомогательной логики, `UpdatedAgo` и документации; миграций нет.
