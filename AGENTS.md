# Инструкции для работы с проектом

## Область действия и источники истины

Этот файл действует для всего репозитория. Более локальный `AGENTS.md` уточняет правила для своей подпапки.

Перед изменениями прочитайте конфиги и ближайший код области задачи. Фактическая конфигурация и исполняемый код приоритетнее описательной документации при расхождениях.

Проверяйте `git status --short` до начала работы. Не исправляйте попутно чужие изменения и не включайте их в коммит. Ограничивайте diff задачей пользователя.

Идентификаторы и код пишите на английском. В документации, комментариях и пользовательском тексте сохраняйте язык окружающего файла.

## Проект и ограничения runtime

Это небольшое Expo / React Native приложение: Expo SDK 57, React 19, React Native 0.86 и TypeScript 6. Сейчас используется один экран без роутера. Приложение запускается в Expo Go и в браузере через React Native Web.

- Сохраняйте совместимость с Expo Go. Не добавляйте нативные модули, требующие development build.
- Не добавляйте роутер, нативные проекты или новую архитектуру приложения без необходимости в задаче.
- Учитывайте обе целевые среды: iOS/Android и web. Успешный запуск в браузере сам по себе не подтверждает работу на устройстве.
- TanStack Query и Zod установлены, инфраструктура API подготовлена. Это не означает, что экран уже использует сгенерированные запросы или что Query provider подключён.

## Expo has changed — do not trust your training data

Expo выпускает breaking changes с каждым SDK. Перед написанием кода, затрагивающего Expo или React Native API:

1. Прочитайте major-версию `expo` в корневом `package.json`.
2. Откройте документацию соответствующего SDK: `https://docs.expo.dev/versions/v<major>.0.0/`.
3. Для остальных вопросов Expo откройте `https://docs.expo.dev/llms.txt` и следуйте профильным ссылкам. Не выбирайте API по памяти.

Документация `latest` может описывать другой SDK. Сверяйте примеры с установленными пакетами и учитывайте deprecation notices.

## Пакетный менеджер и зависимости

- Единственный пакетный менеджер — npm. Репозиторий использует npm workspaces: `api` и `packages/api`.
- Устанавливайте зависимости из корня. Единственный lockfile — корневой `package-lock.json`; обновляйте его вместе с соответствующим manifest.
- Для добавления зависимостей приложения используйте `npx expo install <package>`, чтобы сохранить совместимость с SDK.
- Для генератора Kubb требуется Node.js >=22.12; текущая рабочая среда использует Node.js 24.
- Не обновляйте Expo SDK и другие зависимости попутно. Версии Kubb и его плагинов могут различаться: проверяйте совместимость, а не выравнивайте номера механически.

## Архитектура, импорты и TypeScript

- Экран компонует компоненты и hooks. Общую логику размещайте в самой узкой подходящей области и поднимайте выше при появлении повторного использования.
- `packages/api` не должен импортировать код корневого приложения из `src/`.
- Используйте публичный API `@repo/api` для потребления API-инфраструктуры. При добавлении сгенерированных операций экспортируйте необходимые модули через `packages/api/index.ts`.
- Сейчас алиасы `~/`, `@/` и `#/` не настроены в TypeScript. Их наличие в настройке сортировки импортов не делает их рабочими алиасами.
- Сохраняйте `strict: true` и наследование `expo/tsconfig.base`.
- Отделяйте типы через `import type`. Не скрывайте ошибки с помощью `any`, `@ts-ignore` и необоснованных type assertions.
- Не меняйте существующие соглашения об именовании файлов массово вне задачи.

## Форматирование

Единственный форматтер — Oxfmt на Rust. Источник настроек — корневой `oxfmt.config.ts`:

- табы с `tabWidth: 4`;
- single quotes, без semicolon;
- ширина строки 100;
- форматирование JSDoc, сортировка импортов и scripts в `package.json`.

Для локальных изменений используйте `npx oxfmt <paths>`. `npm run format` форматирует весь проект и может затронуть соседние файлы; запускайте его только при соответствующем scope.

Скиллы, generated API output, lockfile и служебные каталоги исключены из форматирования. Не форматируйте и не редактируйте кодген вручную.

Отдельного настроенного линтера приложения сейчас нет. `npm run api:lint` проверяет OpenAPI, а не React Native код. Не объявляйте Oxfmt заменой lint-проверок и не запускайте `npx expo lint` как существующую проверку без учёта того, что он может предложить установку и настройку ESLint.

## API и кодогенерация

Источник истины — `api/src/openapi.yaml` и его `$ref`-файлы в `paths/` и `components/`. Сейчас контракт OpenAPI 3.0.3 пуст: реальные endpoints, предметные схемы и database-клиент отсутствуют.

- Добавляйте только реальные операции backend API с уникальными `operationId`, параметрами и описанными success/error responses.
- Настройка генерации находится в `packages/api/kubb.config.ts`.
- Kubb 5 генерирует TypeScript-типы, Zod-схемы, Fetch-функции, TanStack Query keys/options и hooks.
- Kubb читает исходный `api/src/openapi.yaml` напрямую. Redocly bundle — отдельная команда, а не обязательный вход генератора.
- `packages/api/base/codegen/` полностью принадлежит генератору. При `clean: true` ручные изменения могут быть удалены.
- Файлы `.kubb/client.ts`, `.kubb/serializers.ts` и `.kubb/standardSchema.ts` — общий runtime Kubb. Не заменяйте их копиями из другого проекта.
- Настройка приложения находится вне codegen: `base/client.ts`, `base/expo-transport.ts`, `base/client-handlers.ts`, `base/mock-client.ts` и `base/mock-scenarios.ts`.
- Сетевые запросы нашего транспорта выполняются через явный импорт `fetch` из `expo/fetch`. Не добавляйте Axios как параллельный HTTP-клиент.
- Общую сериализацию параметров и тела запроса выполняет Kubb. Не дублируйте её вручную без конкретного несовпадения с контрактом.
- Обработчик `401` допускает не более одного повтора с обновлёнными заголовками; refresh не должен рекурсивно использовать тот же retrying client.
- По умолчанию GET/HEAD используют подходящий мок при сетевой ошибке или `5xx`. Без подходящего маршрута сохраняется исходная ошибка. Записи, `4xx`, отмена запроса и ошибки валидации не подменяются мок-успехом.
- Реестр моков пока пуст. Не восстанавливайте данные и сценарии старого проекта.
- Импорт через публичный API настраивает default generated client. Прямой импорт generated hook в обход этой точки может пропустить подключение Expo-транспорта.

После изменения контракта или генератора выполните генерацию, проверку типов и повторную генерацию без изменений результата. Исходный контракт и codegen коммитятся; `api/dist/` — промежуточный игнорируемый артефакт.

Подробности: `api/README.md` и `packages/api/README.md`.

## Рабочий процесс и критерии готовности

1. Проверьте исходное состояние рабочего дерева и прочитайте ближайший код, конфигурацию и профильные инструкции.
2. Делайте минимальный связный diff. Для кодгена меняйте источник или генератор, затем регенерируйте output.
3. Отформатируйте изменённые файлы и выполните соответствующую проверку форматирования.
4. Обязательно запустите `npm run typecheck` или `npx tsc --noEmit` перед завершением задачи.
5. Для изменений API выполните применимые `api:lint`, `api:bundle` и `api:generate`. Для изменений поведения проверьте соответствующий сценарий в доступной среде.
6. Перечитайте итоговый diff. Отразите изменение публичного API или архитектуры в профильной документации.
7. В результате перечислите фактически выполненные проверки и явно укажите, если запуск на устройстве или в браузере не проверялся.

Не объявляйте весь проект исправным по результатам одной узкой проверки. Не включайте соседние изменения и служебные файлы в коммит без запроса пользователя.
